# ADR-0015: Seeker's Carry (R2/R3) — a way of looking, and one line in the seeker's own words

- **Status:** proposed
- **Date:** 2026-09-30
- **Authority:** Founders (Appendix B dependency OPEN: Shalom Ormsby to confirm)
- **Supersedes:** —

## Context

ADR-0014 (R1) shows a returning seeker their own earlier words. R1 is read-only. The founders
also want the reading to leave the seeker with something to do with their own attention afterwards,
without the instrument assigning homework, measuring the seeker, or interpreting them.

Two seeker-side acts fit inside that line:

- **R2, a way of looking:** one of four fixed invitations, each beginning "notice" ("notice where
  it shows up", "… where it does not", "… who is near when it does", "… what comes just before it").
  Looking only: no task, no goal, no fix.
- **R3, one line in the seeker's own words:** at most 200 characters.

On a later visit the return screen gives back exactly what the seeker chose, dated, with nothing
added. Nothing is asked of them in between.

Governance dependency (OPEN): as ADR-0014. This feature is gated by `carryEnabled()`, which requires
every trajectory gate (`ELDER_TRAJECTORY_ENABLED`, `MARKER_CONFIRMATION_READY`, `CEILING_RATIFIED`)
AND `ELDER_CARRY_ENABLED`, so R1 can be lit without it. Shalom must confirm it sits inside the
Appendix B synthetic-intimacy ceiling before any of these flags are flipped. The menu wording has
had no lineage or voice review.

## Decision

A signed-in seeker MAY, after a reading, carry one static way of looking and/or one line in their
own words, and the return screen MAY give it back to them alone, unchanged and dated; the system
never tracks, prompts about, interprets or models what they carried.

Enforced by `lib/returning/carry.ts`, `carry.test.ts` and `scripts/check-carry-register.mjs`
(`npm run check:carry`):

1. The menu and all copy are static; every practice begins "notice".
2. No tracking or outcome language (completion, streak, goal, reminder, "how did it go"), no change
   claims, no Elder voice, no instruction to the seeker.
3. Isolation: only `lib/returning/carryLedger.ts` touches `seeker_carry`; only the carry route
   imports the ledger; neither imports a prompt builder. The line is sent to no model except the
   welfare classifier that already gates every free-text field (as `confirm-marker` does for
   reshaped words). A crisis or distress reading stores nothing and fails toward silence.
4. Gate and session scope live in the route. Release (DELETE) is never gated: a seeker can always
   remove what they carried.
5. Shown on return only after 12 hours, and only the most recent carry.
6. One carry per reading (unique index); releasing a reading, a chain or the account removes it
   (ON DELETE CASCADE).

## Consequences

- One new table (`migrations/027_seeker_carry.sql`); otherwise no change to existing tables.
- The line is stored in plaintext and is readable by anyone with database access. The UI says
  "kept for you", not "private". The privacy disclosure that covers readings should be extended to
  cover carried lines before launch.
- A crisis-tier line is not stored and the seeker is shown nothing (same posture as a reshaped
  marker). Surfacing crisis resources here is a possible follow-up and is not built.
- There is deliberately no follow-up: the system never asks whether the seeker did it or how it
  went. Anything that would ask needs a new ADR.
- English-only copy; the practice menu is four items on purpose. Adding one is a governance edit
  of this ADR, not an engineering change.
- Shared-screen privacy: the return screen shows the seeker's line on arrival; "Set this down"
  hides it for the session and "Release this" deletes it.
