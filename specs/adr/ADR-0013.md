# ADR-0013: Corpus Retrieval Backend Architecture

- **Status:** accepted
- **Date:** 2026-08-18
- **Authority:** Engineering
- **Supersedes:** —

## Context

Per the 2026-07-07 session handoff (`docs/handoff-2026-07-07.md`, finding #6), `corpus_passage`
and `retrievable_passage` were empty and unqueried: no voice had real retrieval, and every
Reading's `⧁CORPUS:…⧁` marker was the model self-reporting a training-data recollection, never
a citation of lineage-reviewed text. `renderProvenanceBlock()` was worded to say so honestly.
That left an open roadmap question — build genuine retrieval, or formalize honest self-report as
permanent — deferred to "Jesse, Vincent, Shalom."

This ADR does not resolve that question for every voice. It records what was actually built for
one voice (`mekubal`) once real lineage-reviewed source text became available (Getzel Davis,
accountability holder, `consent_grant` row seeded 2026-07-15), and the backend architecture now in
place for any future voice that goes the same route. Voices without approved corpus content keep
the honest self-report/silence posture unchanged — this is additive, not a replacement of ADR
posture elsewhere.

## Decision

Retrieval is real, narrow, gated, observable, and fails soft toward honesty rather than toward a
fabricated citation. Concretely:

### 1. Schema — one shared table, gated by two columns

`corpus_passage` (original shape: `scripts-resilience/schema.sql`) holds passages for every voice
that has any, discriminated by `lineage_key` (pre-existing column; NOT the `voice_key` column
briefly introduced and then removed in migrations 012–013 — see "Corrections" below).

The **build gate** is the same mechanism ADR-0010 established for K'iche' content, unchanged:
a passage is retrievable only if `review_status='approved' AND ceremonial_sensitivity='open' AND
body_normalized=TRUE AND embedding IS NOT NULL` — enforced structurally by the
`retrievable_passage` view, not by application-layer discipline. Nothing reaches a seeker without
having passed through that view.

### 2. Sourcing — fetch real text, never fabricate it

`scripts-resilience/zohar_pull.py` pulls Aramaic/Hebrew Zohar text from Sefaria's public API by
ref, reporting Sefaria's own license metadata rather than assuming "on Sefaria" means public
domain. `scripts-resilience/suggest_passages.py` extends this: it probes Sefaria's actual index
shape for a parasha (never guesses paragraph ranges), skips anything already sourced (checked
against local JSON *and*, if `DATABASE_URL` is set, the live DB directly), and writes candidates
to `corpus/mekubal-candidates.json` — always `review_status: 'draft'`, never auto-merged.

Both tools exist because the alternative — asking a model to produce Aramaic/Hebrew scripture from
memory — risks silently fabricating "sacred text" with wrong wording presented as authoritative.
Real sourcing tools were built specifically to avoid that.

### 3. Review — a human names themself, on a real date, for specific passages

`corpus/mekubal-passages.json` is the reviewed/committed file; `corpus/mekubal-candidates.json` is
the unreviewed staging file. Moving an entry from candidates → passages requires setting
`review_status: 'approved'`, `reviewed_by`, and `review_date` to real values a human supplied —
never a placeholder or an assumed "today." This mirrors the correction already made to the
`ojer_tzij` consent ledger in the July 7 handoff (a fabricated holder name/date was treated as a
real incident worth fixing, not a formality).

### 4. Ingestion — one script, two gates enforced in code

`scripts-resilience/ingest.py` is the single door (per its own header comment, echoing La Baluka's
publication gate) through which content enters or leaves the index:

- **Normalization gate**: NFC + canonical-form normalization runs before storage;
  `body_normalized` is set `TRUE` only as proof the gate ran.
- **Build gate**: only `approved` + `open` passages are embedded; everything else is stored
  without an embedding and is therefore structurally invisible to `retrievable_passage`.
- **`voice_key` is a required JSON field**, mapped to the `lineage_key` DB column, with no
  fallback default — see "Corrections" for why this changed from optional to required.
- `--dry-run` validates JSON shape, normalization, and build-gate outcome with no DB connection
  and no embedding API call — the check every ingest is run through first.

Embedding: **Voyage AI `voyage-multilingual-2`**, 1024 dimensions, chosen to match the actually
deployed `corpus_passage.embedding` column (`vector(1024)` — see "Corrections") and because it is
built for multilingual text, a better fit for Hebrew/Aramaic than a general-purpose embedding
model. Anthropic recommends Voyage as its embeddings partner since Anthropic's own API has no
embeddings endpoint.

### 5. Retrieval — real query, real grounding, real provenance

`lib/corpusRetrieval.ts`'s `retrieveForVoice(voiceKey, seekerText, limit, onAnomaly?)`:

1. Embeds the seeker's latest message via the same Voyage model/dims used at ingest time (a
   mismatch here would produce meaningless similarity scores, not an error — this can't be
   caught automatically, only kept in sync by convention, documented at both call sites).
2. Runs a `pgvector` cosine-similarity query against `retrievable_passage`, scoped to
   `lineage_key = voiceKey` — so a query only ever surfaces passages belonging to the voice that's
   actually speaking.
3. Returns `[]`, never throws, on any failure — missing config, embed API errors, DB errors, or a
   legitimately empty result set are all non-fatal to the Reading itself.

`app/api/divine/route.ts` calls this once per request, **after** the voice-enabled and consent
gates (no reason to spend an API call + DB query on a voice about to be blocked or withdrawn), and
uses the result two ways:

- Injects matched passage text into the system prompt as grounding, with an explicit instruction
  to draw on it directly rather than from general recollection, and not to force a connection that
  doesn't fit.
- Populates `ReadingProvenance.passages` with the *real* retrieved rows — replacing what was
  previously a hardcoded `[]`.

`src/resilience/provenance.ts`'s `renderProvenanceBlock()` branches honestly on that: non-empty
`passages` now means genuine retrieval happened, and says so ("retrieved from lineage-reviewed
source text"); empty means the existing honest fallback ("not grounded in specific passages...
reflection only, not transmission") — unchanged for every voice without approved corpus content.

### 6. Observability — distinguish "nothing found" from "something's broken"

`retrieveForVoice`'s fail-soft design is correct for the Reading (an outage should never block a
seeker) but was, until this ADR's underlying work, indistinguishable from outside: every error
path and every legitimate empty result looked identical — `[]`. The `onAnomaly` callback (wired to
`route.ts`'s existing `telemetryAllowed()`-gated `logAnomaly()`) reports real failures only —
missing config, embed errors, DB/SQL errors — to `anomaly_record`, tagged `kind: 'near_miss'` with
a bounded, no-raw-seeker-text `note` describing the failure class. A clean "nothing relevant
found" is deliberately never reported, so ordinary readings for voices without a deep corpus don't
flood the table with non-anomalies.

### 7. Standing guards against this recurring

- `scripts/check-schema-drift.mjs` (`npm run check:schema-drift`) diffs a `SELECT *` view's live
  columns against its base table's, for exactly the failure mode found below. Requires
  `DATABASE_URL`; deliberately NOT part of `gk-007`'s static CI tier (that tier is
  no-network/no-secrets/deterministic by design) — run locally after any migration touching a
  wrapped table, or wire into a deploy step.
- `tests/corpusRetrieval.integration.test.ts` (`npm run test:corpus-retrieval`) calls
  `retrieveForVoice()` against the real DB and Voyage API and asserts a real match comes back for
  `mekubal` — kept separate from `tests/resilience.test.ts`, which stays secret-free so it keeps
  running in CI on every commit.

## Corrections made along the way (recorded, not silently absorbed)

Building this surfaced four real bugs, each fixed with a migration and documented at the fix site.
Listed here because the pattern connecting them — schema files, views, and default columns
drifting silently out of sync with the live DB — is the actual lesson, not any one bug:

1. **`scripts-resilience/schema.sql` said `vector(1536)`; the deployed column was `vector(1024)`.**
   Corrected in the schema file; `migrations/011` asserts it against the live DB going forward.
2. **`corpus_passage` already had a `lineage_key` column** (pre-existing, default `'ojer_tzij'`,
   a leftover from when the table served only the K'iche' voice) that was unknown when this work
   started. A redundant `voice_key` column was mistakenly added instead (`migrations/012`), and
   because `ingest.py` never set `lineage_key`, **all 10 real Zohar rows were silently mislabeled
   as `ojer_tzij`** on insert. `migrations/013` backfilled the correct value, dropped the redundant
   column, and `ingest.py` now requires `voice_key` in the JSON with no default.
3. **`retrievable_passage` is `SELECT *`, frozen at CREATE time.** It predated `lineage_key`
   exposure and never picked up newer columns, so `lib/corpusRetrieval.ts`'s query against it threw
   on every call — caught by the deliberate fail-soft design, so retrieval silently returned `[]`
   in what looked like normal operation. Also fixed in `migrations/013` (view recreated); guarded
   against recurrence by `check-schema-drift.mjs` above.
4. **`app/api/log/route.ts` has inserted a `source` column into `anomaly_record` since it was
   written; the column never existed in the DB or in `schema.sql`.** Every anomaly write — not
   just the new corpus-retrieval ones — has been silently failing (caught by the route's own
   `try/catch`, "observatory must never break the response") for as long as that code existed.
   `migrations/014` added the missing column; `schema.sql` corrected to match.

The common shape: **a fail-soft design (correct, deliberate, defends the seeker-facing behavior)
also hides schema drift that a fail-loud design would have surfaced immediately.** None of these
were caught by `tsc --noEmit` or by reading the code — only by querying the live DB directly and,
in one case, by deliberately reproducing the failure to confirm a guard actually catches it.

## Consequences

- Enables real, attributable citation for any voice that goes through this pipeline — not just
  mekubal. The pipeline (`zohar_pull.py`-equivalent sourcing tool → human review with real
  name/date → `ingest.py` → `retrieveForVoice()`) is the template for a second voice, not
  mekubal-specific plumbing.
- Does not change posture for any voice without approved corpus content — self-report/silence
  language is untouched.
- `VOYAGE_API_KEY` must be set in Vercel's production environment, not just `.env.local`, or
  retrieval silently (and correctly, per its fail-soft design) degrades to the honest fallback in
  production. Not yet confirmed done as of this ADR.
- Sefaria reports `license: unknown` for the specific Sulam Edition digitization used for the
  first 10 mekubal passages, even though the underlying ~13th-century Aramaic composition is
  almost certainly public domain regardless of edition. This ADR does not resolve that — it is a
  human call for Getzel/Vincent, tracked as an open item, not blocked on here.
- `check-schema-drift.mjs` is not wired into CI or a deploy gate as of this ADR — it exists and is
  proven to work (verified by deliberately reproducing the original drift and confirming it caught
  it), but running it is currently a manual step.
