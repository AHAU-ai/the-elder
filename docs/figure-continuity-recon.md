# Figure Continuity: FC-0 recon

Read-only confirmation of the build plan's touch points against `main` at `5e8ecd1` (#207, which includes #206). Written 2026-10-04. Each item: the answer, the file, and any divergence from spec v0.1 (patched in spec v0.2).

## Items

1. **Key types.** `elder_user.id` is `BIGSERIAL` (`migrations/001_baseline_myth_accounts.sql`), `getSessionUserId` returns `number | null` (`lib/auth.ts:62`). There is no chains table. A chain is `visit_record.chain_id UUID` (`migrations/008_visit_record_on_elder_user.sql`), minted server-side by `insertVisit` with `chainId: null`, one fresh chain per explore visit (`app/api/divine/route.ts` ~1238-1259). The lineage column is `lineage_key TEXT`, not `voice_id`. **There is no `myth_entry` table.** Approved corpus text lives in `corpus_passage` (`passage_id TEXT PRIMARY KEY`, `review_status` enum, `voice_key TEXT` added in migration 012); several ingest scripts say so explicitly. *Divergence:* spec `user_id`, `chain_id`, `voice_id`, `counterpart_entry_id` all change.
2. **Migrations.** The convention is numbered SQL files in `migrations/`, run with `psql -f` (or the Neon SQL editor), against `DATABASE_URL_UNPOOLED` for DDL under load. `migrations/README.md` says not to add new `scripts/migrate-*.mjs`. Latest is `029_portal_bypass.sql`, so the next is **030**. *Divergence:* plan says `scripts/migrate-NNN-figure-mapping.mjs`; it should be `migrations/030_figure_mapping.sql`. Run `npm run check:schema-drift` afterward.
3. **Figure marker and "confirmed".** Per-visit: `visit_record.markers` (proposed) and `visit_record.markers_confirmed JSONB` (co-authored subset, keys `wound|figure|threshold|exile|pattern`; `MythicMarkers` in `lib/returning/visit.ts`). Cross-visit: `marker_trajectory (user_id, marker_type, marker_value)` with a case-insensitive unique index (`migrations/009`), plus `depth_stage` (`020`). A figure is "confirmed" for a chain when some visit in that chain has `markers_confirmed.figure`. Confirm flow: `app/api/elder/confirm-marker`. There is no `mythLedger.ts`. *Divergence:* the "home chain" is derived, not stored.
4. **READY_SIGNAL.** It does not exist as a named constant. The route uses inline sentinel strings with the delimiter U+29C1: `⧁⧁READY⧁⧁` (`includes` then single `replace`), `MORE_TOKEN`, `⧁CEILING:<x>⧁` and `⧁MYTH:<x>⧁` (regex, global strip) at `route.ts` ~919-985. Parsing runs on the raw text and stripping happens before the dual guardian sees it. **There is no streaming:** `client.messages.create` returns one JSON response. *Divergence:* the signal is `⧁MAPPING_OFFER:{json}⧁` in this family, and the streaming-leak risk in the plan does not apply.
5. **Context and prompt builder.** `effectivePriorMythContext` is a local variable in `route.ts` (~578), not an exported function. `assembleDeepContext(userId: number, chainId: string)` is in `lib/returning/visit.ts:219`. `buildSystemPrompt` (`lib/system-prompt-builder.ts:238`) takes **positional** parameters ending in `openingMessage`, `segmentIndex`; a new block is a trailing optional parameter. `renderProvenanceBlock(p)` lives in `src/resilience/provenance.ts:125` and is called at `route.ts` ~1161, after generation.
6. **Flag pattern.** `config/returning-features.ts`: `FEATURES.ELDER_TRAJECTORY` from `ELDER_TRAJECTORY_ENABLED`, plus `MARKER_CONFIRMATION_READY` and `CEILING_RATIFIED`, composed in `trajectoryEnabled()`. Copy that shape for `figureContinuityEnabled()`.
7. **Tier and register.** `getTierRecord` and `deriveEffectiveTier` (`lib/tierLedger.ts`); the route computes `effectiveTier` and `tierIsKeptPlus = effectiveTier !== 'seeker'` (~508), and `tierRecord.isTester`. Tiers are `seeker|...` (check `Tier` in `tierLedger.ts` for the exact paid names before FC-C). Register: `getNarrativeRegister(userId)` (`lib/narrativeRegister.ts`) resolved into `resolvedRegister` (`'child' | 'young_adult' | 'adult'`). Entitlement: `checkTierEntitlement` (`lib/tierEntitlement.ts`).
8. **Welfare gate position.** `assessWelfare` runs inside a `Promise.all` (~380-412), before prompt assembly. Downstream blocks already gate on `!welfare.surfaceResources` (chain graft ~531, archetype ~561, trajectory ~640-673). The crisis hard-block returns at ~817, **after** the system prompt is built and before any model call. Crisis is `welfare.tier === 'crisis'` with `surfaceResources`; the distress tier has `allowPsychopompLayer=false`, `surfaceResources=false`. Mapping gating must follow the same `!welfare.surfaceResources` pattern and, as a decision for Jesse (D8), also be off at distress. This touches welfare-adjacent gating, so it needs an explicit call per `CLAUDE.md`.
9. **Release paths.** `releaseVisit`, `releaseChain`, `releaseAllVisits` in `lib/returning/visit.ts:141-168`. HTTP: `DELETE /api/user/history` (one visit or one chain, fails loud with 500) and `DELETE /api/journal` (releases all visits, readings, archetypes, synthesis). `figure_mapping` has no FK to `visit_record`, so each release path needs an explicit mapping delete. Open question: deleting a single visit can strand a chain's mappings (no remaining visits).
10. **Arrival moment.** `GET /api/user/history?head=1` exists (`mostRecentChain`) but **has no client caller** in `app/`. Real continuation today: `Threshold.tsx` `myth-transition` with `continuingMyth` from saved myths, and `CouncilTabs.tsx` "Deepen this myth" sending `chainAction: 'deepen'` (~593-616, ~950). `mostRecentChain` is the most recent chain, not the figure's home chain. *Divergence:* FC-E needs a new server-reported capability field; it cannot rely on the head lookup as written.
11. **Test harness.** `scripts/drift-detect.mjs` holds a `PROBES` array in-file (24 entries, shape `{id, category, voice, message, assert, requireRefusal, refusalSignals, rationale}`); config in `scripts/drift-detect.config.json`. Check scripts: `scripts/check-*.mjs`, wired as npm scripts and as steps in `.github/workflows/gk-007.yml` job `gk-007-static` (Node 18, `npm ci --ignore-scripts`, no network or model). Model probes run in `gk-007-probes` and `drift-detect.yml` with an infra preflight. `check:unwired-exports` fails any exported `lib/`/`src/` function with no real caller, so FC-A/FC-B ledger functions must be wired in the same PR or exempted explicitly. `CONTRACT_HASH` appears in `lib/narrativeForm.ts` and `lib/dt1-directional-transformation.ts`; check whether prompt text feeds it before FC-C.
12. **Branch protection.** Not classic protection (404). Ruleset `GK-007 Covenant Integrity Gate` (id 19156061, active, default branch): no deletion, no non-force-push, PR required with 0 approvals, required status check `gk-007-static`. One bypass actor (the owner's user, `always`). So PRs merge once `gk-007-static` is green; direct push by the owner is possible but is not the procedure.

## Stack corrections for the plan

- `next` is `^16.3.1`, not 14. `AGENTS.md` warns APIs differ; read `node_modules/next/dist/docs/` before route work (the plan's "Next.js 14" is wrong).
- Local Node is 24; CI is Node 18. New scripts must run on 18.
- `/api/divine` rate limiting is IP-based (`checkRateLimit(ip, limit)`, `lib/rate-limit.ts`, DB-backed via `rate_limit_bucket`, migration 019). Mapping routes need a per-user key; reuse the ledger with a different key rather than the IP path.
- Single response, not streaming, so the plan's streaming-boundary tests drop out; the real ordering risk is strip-before-guardian.
